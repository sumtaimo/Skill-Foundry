# Layer 05: Rules

The rules are in SKILL.md and `RULES.json`. How to apply them at each step:

1. R-component-kit-1: before any work, `status` decides. No `design/tokens.css` means one sentence and no file.
2. R-component-kit-2 and 3: choose the step and at most four components before you write anything; the rest of the request goes to STATUS.md.
3. R-component-kit-4: a spec with a missing section or state fails the checker; write the section instead of arguing with the checker.
4. R-component-kit-5: search the name in `tokens.css` before you write it. A name you remember from another project is not a name you may use.
5. R-component-kit-6: the nearest semantic variable is used now; the wanted variable is only a request to design-system.
6. R-component-kit-7: no spec, no code. The spec is also the place where a decision is made once.
7. R-component-kit-8 and 12: a literal value in code is a defect even when it looks the same as the variable today, because the next `set` will not reach it.
8. R-component-kit-9: quote the result line of the checker; "passed" without a PASSED line is a false report.
9. R-component-kit-10 and 11: the contract and the Khmer handling are not extras; a component without them is not done.
10. R-component-kit-13: a demo is not a screen. It shows components, in states, and nothing else.
