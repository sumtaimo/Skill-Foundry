# Layer 02: Context

1. Run `node <skill folder>/engine/spec-check.mjs status` as one plain command from the project root. It tells you whether `design/tokens.css` exists, which of the twelve components already have a spec and whether it passes, and which variables earlier specs asked for.
2. When it prints NO DESIGN FOLDER, stop and follow layer 06, step 1.
3. Read `design/BRIEF.md` (small): product, archetype, font, density. It decides tone and which variants a spec needs. Read `design/STATUS.md` for the last step and the words to continue.
4. Open `design/tokens.css` only to search for names (a name search such as `--button-`, `--color-action`, `--space-`), not to read it whole.
5. Read an existing spec before you change it, and keep its decisions. A spec that fails the checker is fixed, not rewritten from nothing.
6. CODE step only: find the stack. Look for `package.json` (react, vue, svelte, tailwindcss and its version, a CSS-in-JS library), `tailwind.config.*`, `*.vue`, `*.tsx`, `*.css` and `*.scss` in the project. Note the folder where components live (the project's existing components folder when one exists).
7. Never edit `design/variables.json`, `design/tokens.css` or `design/design-tokens.json`. They are generated by design-system.
