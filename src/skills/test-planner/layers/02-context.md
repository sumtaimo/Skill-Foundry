# Layer 02: Context

1. Treat the change text as the only source of areas, screens, fields, rules and behaviour.
2. When the input is a diff, read only what it contains: file names, function names, route names and visible labels in the changed lines.
3. Keep the user's own names for areas, fields and messages exactly as written, including capital letters.
4. Keep any background the user adds (for example, "payments are risky") as a separate note marked as the user's statement, so it can be quoted as a source phrase.
5. Do not look up the product, its code or its documentation. The skill runs in any project, and only the change text is known.
6. Hand the list of names and the user's notes to layer 03.
