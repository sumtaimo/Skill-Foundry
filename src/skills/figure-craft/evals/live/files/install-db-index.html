How a database index speeds up a lookup

Table rows sit in the order they arrived. Without help, the database must read them one by one. An index keeps the same keys sorted, each with a pointer to its row. Sorted keys can be searched by halving, so the database finds the pointer in a few steps and jumps straight to the row.

Why it matters at scale

With 8 rows the gap is small. A scan grows with the table, so a million rows can mean a million reads. A sorted index halves the search at each step, so a million keys take about 20 steps (220 is just over a million).

The cost: every insert or update must also keep the index sorted, and the index takes its own space.
