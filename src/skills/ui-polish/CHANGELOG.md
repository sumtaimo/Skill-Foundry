# Changelog

## 1.0.0 - 2026-11-15

- First version: a final polish pass on finished UI code, with numbered fixes tied to rules R-ui-polish-1 to R-ui-polish-19 and the full polished code.
- Fixed numeric scales for spacing, type, line-height, weight, radius, width and target size; a contrast formula and table in references.
- Keeps every word of text, every element and every brand hue; works in plain CSS, JSX and utility classes without converting between them.
- Exact sentences for no code, a new-design request and a text-rewrite request.
- Eval case `text-rewrite-declined` expected 2.85:1, the ratio on white; the banner background is #f9fafb, so the right ratio is 2.73:1. The first real recording found the case was wrong.
- Token mode: when the project has a token file made by a design-system skill (`tokens.css` and/or `design-tokens.json`, pasted, named by the user, or found in the project), fixes are written with its tokens (`var(--space-12)`, `var(--color-text-muted)`, `var(--radius-control)`), the token scales replace the default scales, and the one primary action uses the primary-fill tokens (`--color-action-primary-bg` with `--color-action-primary-text`). A value with no matching token stays a plain value and goes under Open questions; a token name is never invented; the token file is never edited, and a token pair that fails its ratio is kept and reported with the ratio. New rules R-ui-polish-20 to R-ui-polish-23, new reference `references/tokens.md`, new fix area **Tokens**. Without a token file the skill works exactly as before (default scales); the skill still does not need any other skill installed, it only reads the file format.
- Contrast script `engine/contrast.mjs` (Node.js standard library only, read-only): exact ratios for hex or token pairs, light and dark, the nearest same-hue shade that passes, a whole scale against one background. Rules R-ui-polish-24 and R-ui-polish-25: ratios come from the script when commands can run, else from the reference table, and the reply says which in one fixed sentence. This replaces hand arithmetic: a fresh agent in the first release wrote 7.14:1 where the real ratio is 7.13:1, and agents without the script were again 0.01 off on pairs that are not in the table (4.62:1 for 4.63:1). The reference table was rebuilt from the script and now also has the backgrounds #f9fafb and #f3f4f6 (the table had values up to 0.01 high before).
- Four new live eval cases (12 in total): `tokens-css`, `tokens-tailwind` (Tailwind and JSX with CSS variables), `tokens-no-match` (a value with no matching token) and `tokens-fail-contrast` (tokens that fail contrast). `settings-card` and `tailwind-jsx` also check that default mode never writes `var(--`. All 12 were re-recorded with fresh agents; `tailwind-jsx` and `text-rewrite-declined` were run without permission to run commands, on purpose, to exercise the reference-table and by-hand paths of the ratio sentence.
- Fixes made to the skill after real agents failed: the reply had a sentence before its heading (now forbidden, also for notes about checks), a "fix" that changed nothing was listed, the Tokens sentence was reworded by an agent, an agent wrote a 48 px target with no `44px` in the code (now `min-height` and `min-width` of 44 px are always written), and a Motion change was written as a loose line. `brand-hue-kept` was not changed.
- Routing: the description now mentions token files and design-system as the neighbour; two routing cases added (`r-uip-1`, `r-uip-2`).
- Recipe `tokens-then-polish` (design-system, then ui-polish) in `src/factory/recipes.json`, recorded by a real agent.
- Improvement from real use on our own site (S1, S2, S3 of `docs/factory/STATUS.md`), same version 1.0.0:
  - S1: the contrast script is run as one plain command with the full path (`node <skill folder>/engine/contrast.mjs ...`), with no `cd`, no variable, no pipe; agents had chained `cd …; VAR=…; node …`, sandboxes refused it and the agent fell back to hand work. When the script cannot run, the reply says so plainly. New rule R-ui-polish-26.
  - S2: never lower a passing pair (a near-black primary button at 16:1 had been replaced by brand green at 4.9:1); never replace a passing value with a different token value, it goes under Open questions with both values; a token file that was found but is not loaded by the page is reported and not used. New rules R-ui-polish-27 to R-ui-polish-29; rule 21 and layer 06, step 14 now give way to rule 28.
  - S3: optional screenshot or measurement sheet; with one, text that overflows or overlaps its box is fixed with the measurement quoted; without one, the skill does not claim to have checked order, page length, overflow or overlap. Pages that share one stylesheet get one stylesheet patch plus a delta per page. New rules R-ui-polish-30 and R-ui-polish-31.
  - The description is unchanged, so routing was not re-recorded.
  - Two eval cases were changed because the approved rules changed what is correct, not to make a failing agent pass: `shared-stylesheet` (new) does not expect the unchanged markup of pages that only get a delta; `tokens-css` used to require that a passing blue primary button (5.17:1) be replaced by the project's teal fill token; under rule 28 the real agent now keeps the blue and asks under Open questions, so the case expects `--color-action-primary-bg`, `#2563eb` and `#0f766e` in that question. The recording was not touched.
  - All 12 old live cases were re-recorded with fresh agents after the change, plus 4 new cases (16 in total).
