# Layer 09: Handoff

1. Give the review as the whole reply. The skill writes no file and changes nothing in the project.
2. The reader receives: the numbered findings, most severe first; the open questions to answer before the next review; the list of what was not reviewed.
3. The findings are written for the person who changes the screen. Each recommendation says what must be true afterwards, so the fix can be checked against it.
4. Work the review leaves to others, named only by its kind: changing the code of the screen is a visual polish or development task; wording is a copy edit; contrast, semantics and screen-reader output are a polish pass and an accessibility audit. When the project has a skill for one of these, the reader starts it; this skill never does that work itself.
5. After the screen changes, the same input format can be reviewed again; finding numbers are not kept between reviews, places and rule ids are.
6. Hand the counts (steps, findings per severity, open questions) to layer 10.
