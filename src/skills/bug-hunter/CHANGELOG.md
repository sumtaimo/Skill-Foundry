# Changelog

## 0.1.0 - 2026-11-22

- First version: hunts for real bugs in a project's code, read-only and in the reply. Runs the project's own test command (`npm test`, or `node --test` when there is no `test` script) and nothing else, reads the code in scope, and reports each finding as confirmed (the test output shows it, quoted word for word) or suspect (code reading only, with `file:line`, a concrete input and the wrong result).
- Every finding has a Red-Green plan: the failing test to add first (or the test that already fails), then the smallest fix at the cited line.
- Never invents a bug or a business rule: the expected result names its source (a failing test, the request, a project comment); never reports style; never says the code is bug-free.
- Fixed sentences for no code, a regression-checklist request (test-planner), a style or accessibility request (ui-polish, a11y-audit), a request to fix or write files, no test command, and no finding.
- Requested by Agentic-Harness for QA_AUDITOR: its read-only `[HARNESS HUNTER]` planner call (1.0.39) matches "bug hunt regression tests: <scope>"; the keywords are longer whole phrases so bug-hunter ranks first under the cap of 2.
- Eval case `uncovered-suspect` now checks "0 confirmed" instead of "0 confirmed, 1 suspect": the first real agent also found a second real bug (`excerpt` cuts an emoji in half, against its own doc comment "the first `max` characters"), so the exact count was wrong, not the agent.
- From the first real run: a function checked and found fine is named only in "Files read" (an agent wrote a paragraph about it), and the project is listed with the list and search tools only (an agent tried a shell `find`).
- From the second real run: an agent reported `clamp(NaN, 0, 10)` as a suspect with an expected value "the project needs to decide". A suspect now needs an input of the kind the project already uses and an expected result a source states; `NaN`, `null` or a wrong type count only when a caller passes them or a source mentions them (layer 04, step 6; references, part 1).
- Eval case `uncovered-suspect` now checks the cited cause `replace(' ', '-')` instead of the word `replaceAll`: an agent gave an equally correct fix (`replace(/\s+/g, '-')`), so the case named one fix where several are right.
- From the third real run: an agent read the code with a shell `cat`, which shows no line numbers, and cited `orders.js:10` for code on line 9. SKILL.md now says before the first tool call: run only the test command, and read and list files with the read, search and list tools, which show line numbers (layer 07 checks each cited line).
- The task's own format and file come first: a required output format (JSON only) replaces the Markdown report, each finding keeping its status, `file:line`, Red and Green (R-bug-hunter-14); a test file the task assigns gets the Red tests, never the fix, and the test command runs again so a suspect becomes confirmed or is dropped (R-bug-hunter-15). Learned from the Agentic-Harness risk check of journey-mapper; live cases `json-format` and `assigned-test-file`.
- Keywords are whole phrases of at least 4 characters ("bug hunt", "hunt", "regression test", "regression tests", "edge case", "crash", "broken", "bugs"): on "bug hunt regression tests: <scope>" they give 4 hits with the longest phrase, so bug-hunter ranks first over test-champion and security-guard; plain "regression" is left to test-planner, so "give me a regression checklist" never loads bug-hunter.
- Code pasted in the request is a scope, cited as `pasted:<line>`, with no test command (the portable check runs in an empty project, where a pasted snippet would otherwise get "No code found"); live case `pasted-code`.
