# Layer 03: Inputs

Required:

1. The requirement text: at least one statement of what the product must do. A title, a feature name or a single word is not enough.

Optional:

2. A feature or ticket name, used in the document heading.
3. The roles involved, when the text names them.

When one is missing:

4. Nothing but the request, with no requirement text and no title (for example only "Write acceptance criteria for this feature."): the whole reply is exactly "Paste the feature request, user story or requirement you want acceptance criteria for." Stop. Write no clause and no heading.
5. A title or feature name only, with no statement of what it must do (for example "the new export feature"): do not use clause 4. The whole reply is exactly "Describe the requirement for <the title in the user's words>: who uses it, what they do and what must happen." Stop. Write no clause and no heading.
6. Never fill a gap with a guess about the product.
7. Hand the complete requirement text and the optional inputs to layer 04.
