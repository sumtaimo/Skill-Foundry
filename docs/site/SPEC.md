# Showcase site specification

Static, zero-dependency site generated by `node src/site/build.mjs` from `src/factory/registry.json` and `src/skills/<name>/`. Only skills with `status: "ready"` appear. No invented facts: no download counts, no test counts, no dates.

Signature: one line in, skill out. Specimen plates. An honest quality meter. Four questions per skill. Inter only, one accent colour.

## 1. Pages

### 1.1 `index.html` (Collection)
**The collection shows what goes in and what comes out, before anything else.**

1. Plain top bar: site name, Collection link, language and theme buttons. No rail, no pointer, no numbering.
2. Hero `<section class="hero">`:
   - `<div class="hero-prompt">`: mono prompt box. The full prompt text of the selected skill is in the HTML; `site.js` only types it out.
   - `<div class="hero-figure">`: the selected skill's inline cover SVG. Its parts carry class `hero-part` and slide in along iso axes, one after another, after the prompt is typed.
   - `<div class="hero-chips">`: one `<button class="chip" data-skill="<name>">` per ready skill, sorted by name. Clicking a chip selects that skill and replays the hero.
   - Reduced motion: prompt text and every `.hero-part` are shown complete, `animation: none`, no transition.
   - JavaScript off: first skill shown complete.
3. Opening line (`index.opening`) and one short paragraph (`index.p1`).
4. Grid of specimen plates, sorted by name. Each `<article class="plate" data-skill="<name>">`:
   - `<span class="plate-index">No. 01</span>`: two digits, by sorted order, in mono.
   - tags at top right
   - inline cover (sanitized `preview/cover.svg`)
   - title linking to `skills/<name>/index.html`
   - `<p class="plate-type">You type: <code>…</code></p>`: `preview.json` prompt, one line, truncated by CSS.
   - `<p class="plate-get">You get: …</p>`: `preview.json` outputs.
   - meter (see 1.4)
   - `<footer>`: version in mono and the download button (see 1.5).
5. "How a skill is made" (`made.*`), "Install a skill" (`install.*`), "Limits" (`limits.*`). Plain headings, unnumbered lists or prose.

### 1.2 `skills/<name>/index.html` (per skill)
**Every skill page answers four questions, in the same order.**

1. Plain top bar, back link (`skill.back`), large cover, title, tagline.
2. Sticky `<nav class="qbar">` with four `<a>` tabs: `#what-it-does`, `#what-you-type`, `#what-you-get`, `#how-you-know`. The active tab uses `--ok`. Inside it, `<div class="qbar-progress">`: a 2px line whose width follows scroll.
3. Four `<section>` elements with those ids, in that order. The first child of each is `<p class="takeaway"><strong>one sentence</strong></p>`.
   - `what-it-does`: procedure from `SKILL.md` `## Procedure`, ordered list.
   - `what-you-type`: the `prompt` with a copy button.
   - `what-you-get`: outputs; optional example iframe (`<iframe sandbox="allow-scripts" src="example.html" title="…">`, never `allow-same-origin`, only when `preview/example.html` exists; build copies it to `skills/<name>/example.html`).
   - `how-you-know`: the meter, totals (total, machine-checked, checklist), files in package.
4. Download section: download button, SHA-256 inside an element with `data-sha256`, href ending `downloads/<name>-<version>.zip`.
5. Install section: steps.
6. Changelog: `CHANGELOG.md`, escaped.

Forbidden anywhere: left rail, pointer glyph, `01 / 05` numbering, any class containing `rail`.

### 1.3 `downloads/`
`<name>-<version>.zip` per ready skill, `all-skills.zip`, `checksums.json`, all produced by `packAll` from `src/factory/pack.mjs` (not reimplemented). Unchanged by this redesign.

### 1.4 Quality meter
**The meter shows how many rules a machine checks, and nothing more.**

- `<div class="meter" data-machine="M" data-total="T">` with a bar element filled `M/T` in `--ok`.
- Text exactly `M of T rules machine-checked`. M = rules with `check`, T = all entries in RULES.json.
- No score, grade, star or percentage.

### 1.5 Download button
**Every button says what it does.**

- Text: `Download <name> <version> (.zip, <size>)`, e.g. `Download figure-craft 1.0.0 (.zip, 24 KB)`.
- Size: `Math.max(1, Math.round(bytes / 1024)) + " KB"`, from `zipBytes`.
- Other buttons name their action: "Copy prompt", "Copy install command", "Switch to dark mode".

### 1.6 Assets
`assets/site.css`, `assets/site.js`. All links relative. Only external resource: Google Fonts stylesheet for Inter (400, 500) and JetBrains Mono, with preconnect to fonts.googleapis.com and fonts.gstatic.com. No serif family. No external `<script src>`.

## 4. Design rules

### 4.1 Theme
- Light is the default. A toggle switches to dark; the choice is stored in `localStorage` and applied as `data-theme` on `<html>` before paint. Without a stored choice, `prefers-color-scheme: dark` applies dark.
- Colours exist ONLY in the three token blocks (`:root`, `[data-theme=dark]`, `@media (prefers-color-scheme: dark) { :root:not([data-theme=light]) }`). Everywhere else `var(--...)`.

| Token | Light | Dark |
|---|---|---|
| --bg | #f9f9f8 | #141413 |
| --surface | #ffffff | #1b1b1a |
| --surface2 | #f2f2f0 | #222220 |
| --line | #e8e8e5 | #2c2c2a |
| --line-strong | #d4d4d0 | #3a3a37 |
| --fg | #1d1d1b | #ecebe7 |
| --muted | #6f6f6b | #a3a29d |
| --faint | #9c9c97 | #75746f |
| --ok | #2f7a4b | #6cc28f |
| --warn | #8f6200 | #e0b45c |

- One accent: `--ok`. Used only for the active qbar tab, the qbar progress line, the meter fill and focus rings. `--warn` only for build/status errors, never decoration.

### 4.2 Type
**Inter for words, JetBrains Mono for things you type or compare.**

- Inter only: 500 for headings, 400 for text.
- JetBrains Mono: prompts, versions, plate indexes, hashes, paths.
- No serif family. No `font-style: italic` anywhere in site.css. No `<em>` styled italic.
- Khmer text needs a fallback that renders Khmer script (system Khmer font after Inter).

### 4.3 Layout
- Reading column max 600px; plate grid may be wider.
- Plates: 16px radius, 1px hairline border `var(--line)`, background `var(--surface)`.
- Collection uses a plain top bar. Skill page adds the sticky qbar below it.
- No left rail, no pointer glyph, no `01 / 05` numbering.
- Phone: designed at 390px width, 16px side gutter, no horizontal scroll, single-column grid. Qbar tabs scroll horizontally inside the bar if needed.

### 4.4 Motion
- Hero: prompt types out, then cover parts slide in along iso axes one after another.
- Under `@media (prefers-reduced-motion: reduce)`: prompt and every `.hero-part` shown complete, `animation: none`, no transitions, no smooth scroll. Progress line still reflects position without transition.

### 4.5 Clarity rules (all copy)
- At most 3 sentences per paragraph.
- One idea per sentence.
- Every section starts with a bold takeaway sentence.
- Every button says what it does.
- No numbers in copy except the No. index, versions, meter counts and download sizes.

### 4.6 Accessibility
- `<html lang>` set (`en` or `km`). Every element holding skill-sourced content carries `lang="en"`. One `<h1>` per page, headings in order.
- Skip link to main content. Landmarks: `header`, `nav`, `main`, `footer`.
- All controls are `<button>` or `<a>`, keyboard reachable, visible `--ok` focus ring.
- Copy buttons announce "Copied" via `aria-live="polite"`.
- Theme toggle exposes state with `aria-pressed`. Active qbar tab has `aria-current="true"`.
- Cover SVGs are decorative (`aria-hidden="true"`); title is text.
- Text contrast at least 4.5:1 in both themes.
- Site works with JavaScript off, except copy, theme toggle, typing and qbar progress.

### 4.7 Language of content
- Skill-sourced content is never translated: `preview.json` title, tagline, prompt, outputs and tags; procedure steps; changelog text; file names.
- Every element that holds such content has `lang="en"`.
- Site interface text always comes from DICTS (`src/site/lib/i18n.mjs`).

## 3. Finding and installing skills (agents and people)

**A person or an agent can find the right skill by task or role, and install it with one verified command.**

- Roles: each registry entry has `roles` from the harness roles (`PO_ARCHITECT`, `BA_ANALYST`, `DEV_ENGINEER`, `QA_AUDITOR`, see `.harness/roles/`). Plates and skill pages list them.
- Finder above the grid: `<input id="find" type="search">` with a visible label, one `.rolechip` per role in use plus "All roles", a live `.find-count` ("{n} of {t} skills shown") and an empty state `.find-none`. Filtering runs in `site.js` over each plate's `data-text` and `data-roles`; no network.
- Real-agent line on plates and skill pages: "Tested by a real agent: P of T cases pass" from `evals/live/` recordings scored by `scoreLive`, or "Not yet tested by a real agent". Never invented.
- Install command: buttons carry `data-install-zip` and the SHA-256. Over http(s), `site.js` builds `mkdir -p .claude/skills && curl … && shasum -a 256 -c - && unzip … && rm …` from the page address; from a file the button copies the plain `unzip` command. A wrong checksum stops the install.
- Machine index for agents, linked in "For agents": `skills.json` (name, title, version, description, roles, tags, prompt, outputs, page, zip, sha256, bytes, liveEvals) and `llms.txt` (one line per skill with zip, sha256 and real-agent result). Paths are relative to the site root.
